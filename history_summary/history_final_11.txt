## 方案 ② Frida Gadget 注入

### 原理
将 `frida-gadget.so` 嵌入 APK，通过 smali 修改在应用启动时加载。然后用 Frida 脚本 Hook IL2CPP 方法并通过 RPC 暴露数据。

### 通信架构
```
游戏进程
  ├─ libfrida-gadget.so (自动加载)
  │   └─ Frida JS 运行时
  │       ├─ il2cpp hook (frida-il2cpp-bridge)
  │       └─ rpc.exports = { getGameState, getScene, ... }
  │
  └─ Frida Gadget 监听端口 (默认 27042)

uma-helper App
  └─ frida 客户端 / HTTP proxy → 连接 Frida Gadget
```

### 实施步骤
```bash
# 1. 解包 APK
apktool d game.apk -o game_decoded

# 2. 放入 frida-gadget
cp frida-gadget-16.x-android-arm64.so game_decoded/lib/arm64-v8a/libfrida-gadget.so

# 3. 修改 smali，在 Application.onCreate 中加载
#   const-string v0, "frida-gadget"
#   invoke-static {v0}, Ljava/lang/System;->loadLibrary(Ljava/lang/String;) V

# 4. 配置 gadget
# {"interaction": {"type": "listen", "address": "127.0.0.1", "port": 27042}}

# 5. 重打包 + 签名
apktool b game_decoded -o game_patched.apk
zipalign -v 4 game_patched.apk game_aligned.apk
apksigner sign --ks debug.keystore game_aligned.apk
```

### Frida 脚本示例
```javascript
// hook_game.js — 使用 frida-il2cpp-bridge
import "frida-il2cpp-bridge";

        getscene: function() {
            const instance = SceneManager.method("get_instance").invoke();
            return instance.field("currentSceneName").value;
        },
        
        getracedata: function() {
            // 读取比赛数据
            return JSON.stringify(raceData);
        }
    };
});
```

### 优点
- 无 root
- Frida 生态成熟，frida-il2cpp-bridge 直接可用
- 脚本热更新（不改 APK，只换 JS 脚本）

### 缺点
- Frida Gadget 较大（约 20MB）
- 性能开销比 libmain.so 代理大
- 游戏可能检测 Frida（需要反检测）
- 通信需额外封装（Frida RPC → HTTP 桥接）

## 方案 ③ Shizuku + Frida

### 原理
Shizuku 提供 ADB 级别权限（无需 root），可以启动 frida-server（以 shell 权限运行），attach 到游戏进程。

### 优点
- 无 root，不改 APK
- 最灵活（可随时 attach/detach）

### 缺点
- 用户需安装 Shizuku 并通过 ADB 激活（门槛高）
- shell 权限 attach 到游戏进程可能被 SELinux 限制
- 游戏反调试检测（ptrace 检测）
- 每次重启需重新 attach

---

## 方案 ④ VPN 网络拦截

### 原理
利用 Android VpnService 拦截游戏网络流量，解析协议提取状态。

### 优点
- 无 root，无 APK 修改
- 不触发游戏完整性校验

### 缺点
- 只能获取网络传输的数据（内存状态无法获取）
- 需要逆向游戏网络协议
- HTTPS 需 MITM（可能触发 SSL Pinning）
- 无法主动操作游戏

---

## 方案 ⑤ 无障碍服务 + 截屏 OCR

### 原理
通过 AccessibilityService 读取屏幕文本，MediaProjection 截屏 + OCR 识别。

### 优点
- 无 root，无 APK 修改
- 可同时操作游戏（模拟点击）

### 缺点
- 数据精度低（只能看到屏幕显示内容）
- OCR 延迟高
- 无法获取隐藏数据

---

## 方案 ⑥ Hachimi IPC（有 root 时直接用）

如果用户已有 root（Magisk/KernelSU + Zygisk），直接利用 Hachimi 现有 IPC：

```json
// Hachimi config.json
{
    "enable_ipc": true,
    "ipc_listen_all": false,
    "ipv4_only": true
}
```

Hachimi IPC 服务（tiny_http, 端口 4693）暴露了：
- Plugin API（il2cpp_get_field_value, il2cpp_runtime_invoke 等）
- 游戏状态查询
- 翻译数据更新

uma-helper 直接 HTTP 请求 `127.0.0.1:4693` 即可。

## 推荐架构

```
┌──────────────────────────────────────────────────┐
│                  推荐架构                          │
│                                                    │
│  注入层: 方案① Carrotless 式 libmain.so 代理       │
│  通信层: 本地 HTTP Server (localhost:4693)         │
│  辅助层: uma-helper App (HTTP Client + 悬浮窗)     │
│  操作层: 无障碍服务 (模拟点击)                      │
│                                                    │
│  降级方案:                                          │
│  ├─ 有 root → 直接用 Hachimi Zygisk + IPC          │
│  ├─ 无 root + 可改 APK → Carrotless 式注入         │
│  ├─ 无 root + 不改 APK → Shizuku + Frida          │
│  └─ 最低限度 → VPN 拦截 / 无障碍 + OCR             │
└──────────────────────────────────────────────────┘
```

### 具体建议

1. **短期（快速验证）**：
   - 用 Carrotless 的 libmain.so 代理方案
   - 集成 Hachimi-Edge 的核心 Hook 模块（Rust）
   - 开启 Hachimi 的 IPC（端口 4693）
   - uma-helper 通过 HTTP 连接

2. **中期（产品化）**：
   - 基于分析报告中的 Plugin API，写一个 Hachimi 插件
   - 插件暴露游戏状态 JSON API
   - uma-helper 通过 HTTP/WebSocket 获取数据
   - 用无障碍服务实现自动操作

3. **长期（降低门槛）**：
   - 开发一键安装器（类似 UmaPatcher）
   - 自动解包 → 注入代理库 → 重签名 → 安装
   - 用户只需安装一个 APK

### 关键复用点

从 winhttp.dll 分析报告中可直接复用的资源：
- **63 个 IL2CPP Hook 点**：类名和命名空间完全通用（Gallop.* 命名空间）
- **Plugin API**：il2cpp_get_field_value / il2cpp_runtime_invoke 等
- **IPC 设计**：tiny_http + JSON 的通信模式
- **SQLite 查询语句**：直接用于查询游戏数据
- **配置系统**：enable_ipc / ipc_listen_all / ipv4_only
