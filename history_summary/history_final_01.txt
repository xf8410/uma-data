## z-ai CLI 工具用法

### 网页搜索
```bash
z-ai function -n web_search -a '{"query": "关键词", "num": 10}' -o /tmp/result.json
```

### 网页读取
```bash
z-ai function -n page_reader -a '{"url": "https://example.com"}' -o /tmp/result.json
```

### 解析网页内容
GitHub 页面 HTML 噪音很大，直接提取 README：
```python
import re, html
# 从 HTML 中提取 article.markdown-body
readme = re.search(r'<article[^>]*class="markdown-body[^"]*"[^>]*>(.*?)</article>', text, re.DOTALL)
readme = re.sub(r'<[^>]+>', ' ', readme.group(1))
readme = html.unescape(readme)
readme = re.sub(r'\s+', ' ', readme).strip()
```

### GitHub 源码抓取经验
- **raw.githubusercontent.com** 比 GitHub API 更可靠：直接拿纯文本，不用剥 HTML
- GitHub Trees API `recursive=1` 通过 page_reader 调用时常不生效（只返回顶层），需逐层钻取 subtree
- page_reader 返回的 JSON 结构：`data.html` 内是 `<pre>` 包裹的纯文本，用 `re.sub(r'<[^>]+>', '', html)` 清洗即可
- 但 `<` `>` 等字符会被 HTML 转义，Java 代码中的泛型 `List<String>` 会被吃掉，比较运算符也会丢失——分析逻辑时注意这一点

## Rust 交叉编译经验（hlpatch URA Plugin）

### CI 编译失败常见原因
- `sed` 全局替换会搞坏 if-else 路由代码 — 只用 Edit 精确替换
- `handle_http` 返回 `()` — 不能 `return String`，要用 if/else 表达式返回值
- `__builtin___clear_cache` 是编译器内置函数，不能 `extern "C"` 声明 — 用 `core::arch::asm!`
- `ura_log` 是 `unsafe fn` — 在 `catch_unwind` 的 `unwrap_or_else` 闭包里要加 `unsafe { }`
- 常量类型 `usize` vs `i32` — 指针 `.add()` 要求 `usize`，改常量为 `i32` 会导致旧代码编译失败
- 两种结构用不同常量名 — `PARAMS_INCDEC_*_OFF`(usize, plain) vs `PARAMS_INCDEC_DATA_*_OFF`(i32, ObscuredInt)

### IL2CPP 内存布局经验
- `List<T>` 和 `T[]` 内存结构不同：
  - `List<T>` +0x10 = `_items`(T[] ptr), +0x18 = `_size`(Int32), +0x1c = `_version`
  - `T[]` +0x18 = `max_length`(usize), +0x20 = first element
- `ObscuredInt` inline 占 20 bytes: key(4) + hidden(4) + inited(4) + fake(4) + fakeActive(4)
- `read_obscured_int_at(obj, off)` 读 key^hidden 解密
- `read_ptr_at(obj, off)` 读指针
- `read_int_at(obj, off)` 读 plain int32

### GitHub Actions CI
- 获取编译错误日志：`curl -sL -H "Authorization: token xxx" "https://api.github.com/repos/xxx/actions/jobs/JOB_ID/logs" | grep -i 'error'`
- 版本号同步 5 处：Cargo.toml + lib.rs注释 + JSON模板 + GUI heading + 加载通知

## Git LFS 文件下载（无 git-lfs 命令时）
```python
import urllib.request, json, hashlib
# 1. 从 .gitattributes 找 LFS 规则
# 2. 从 LFS pointer 文件读 oid 和 size
# 3. 通过 LFS batch API 下载
url = f'https://github.com/{repo}.git/info/lfs/objects/batch'
req_data = json.dumps({'operation':'download','transfers':['basic'],
    'objects':[{'oid':oid,'size':size}]}).encode()
req = urllib.request.Request(url, data=req_data, headers={
    'Content-Type':'application/vnd.git-lfs+json',
    'Accept':'application/vnd.git-lfs+json'})
resp = urllib.request.urlopen(req)
dl_url = json.loads(resp.read())['objects'][0]['actions']['download']['href']
urllib.request.urlretrieve(dl_url, fname)
# 4. 验证 SHA256
```
- split APK 下载可能不完整（HTTP截断），必须验证 SHA256

## APK/ZIP 解析经验
- base.apk 可能缺少 EOCD（End of Central Directory），Python zipfile 和 unzip 都无法打开
- 解决：手动解析 local file header（PK\x03\x04），逐个读取 entry
- global-metadata.dat 被 Cygames 加密，不在 APK 中（需运行时 Zygisk-Il2CppDumper）
- master.mdb 运行时从服务器下载，不在 APK 中
- libil2cpp.so 中游戏类名被 metadata 加密，SO 字符串搜索只能找到 Unity 引擎层符号

## IL2CPP Method Dump 格式
```json
{
  "ok": true, "total_classes": 27695, "total_methods": 160909,
  "classes": [
    {"class":"ClassName","ns":"Gallop","is_enum":false,
     "method_count":5,"methods":[
       {"name":"get_Field","addr":"0x...","params":0,"return_type":"type_19","static":false}
     ]}
  ]
}
```
- method 是 dict 不是字符串，提取名称用 `m['name'] if isinstance(m, dict) else str(m)`

### 反汇编查询经验
- index.json 的 functions 是 `[file_addr_str, size, il2cpp_addr_str]` 列表，177,385条
- il2cpp 方法表地址(codegen)和实际代码入口地址可能差几字节(0x4~0x14)，找最近匹配
- 查找流程: IL2CPP method dump 拿到 il2cpp_addr → 在 functions 列表里找第三列匹配(或最近) → 得到 file_addr+chunk_file → grep chunk_XXX.asm
- chunk 的 start_vaddr 是文件虚拟地址起点，file_addr = start_vaddr + offset_in_chunk
- IL2CPP List<T> 内存布局: +0x10 = _items(指针), +0x18 = _size(int32), +0x1c = _version
- `bl #0xXXXXXXX` 是函数调用，`adrp+ldr` 对是加载全局变量/常量
- 静态分析能看到客户端查表逻辑(GetRelationPoint 查 MDB 字典)，但看不到服务器端概率表

### 网页内容提取经验
- page_reader 返回 JSON: `data.html` 是原始 HTML
- `<pre>` 标签内容用 `re.search(r'<pre[^>]*>(.*?)</pre>', text, re.DOTALL)` 提取后 `html.unescape`
- Next.js 站点(sppennen wiki/U-tools)的正文内容混在大量 JS chunk 里，用 `re.sub(r'<[^>]+>', '\n', raw)` + 按关键词过滤有效行
- raw.githubusercontent.com/master/ 比 /main/ 更可能成功(老项目用 master 分支)
