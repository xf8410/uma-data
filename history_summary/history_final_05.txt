2. 为什么直接读取 ObscuredInt 会得到 key、444444 或错误值？
   - ObscuredInt 在内存中存储的是异或混淆值，不是真实值
   - 直接读内存 offset 得到的是混淆后的 key 而非解密后的值
   - 必须用 IL2CPP getter 调用才能获得解密后的真实值
   
3. 曾先后尝试的方案：
   - hardcoded offset → 跨版本不可靠
   - 对象头 class → IL2CPP 内部布局变化
   - metadata 动态 field offset → 需要正确解析 metadata
   - cached class/field → 缓存失效问题
   - pure invoke → SIGSEGV 风险
   - pure memory → ObscuredInt 混淆问题
   - 最终回退部分方案：混合使用 getter（安全字段）+ 内存偏移（已验证字段）

二、PIRL 核心思想（从论文+代码 README 提取）
============================================================

PIRL（Policy Improvement Reinforcement Learning）解决的问题是：
  RL 后训练中的"开环优化"——策略迭代过程中，无法判断前一轮更新是有效还是有害。

PIRL 的方案是"前向探索 + 回溯验证"：
  1. 让策略往前走（forward exploration）
  2. 回头看哪些更新真正有提升（backward verification）
  3. 保留好的更新、纠正坏的（selective retention）

PIPO（Policy Improvement Policy Optimization）是 PIRL 框架的具体实现：
  - 即插即用模块（plug-and-play）
  - 可直接接入现有 RL 后训练算法（PPO/GRPO/GSPO/DAPO/SDPO）
  - 核心机制：policy-improvement feedback + historical anchor
  - 维护历史策略锚点，新策略与之对比，按 rho 反馈调节

代码实现位置（从 README 确认）：
  - verl/trainer/ppo/layback_utils.py — feedback 和 anchor 逻辑
  - verl/trainer/ppo/core_algos.py — PIPO 调制目标函数
  - verl/trainer/ppo/ray_trainer.py — 训练循环集成
  - verl/trainer/config/algorithm.py — PIPO 配置

实验场景（从 README 确认）：
  - PPO 数学推理（MATH-style RL tasks）
  - 代码 RL（TACO, LiveCodeBench v6, HumanEval, MBPP）
  - 工具使用 RL（ToolRL/RLLA, BFCL, APIBank）

四、PIRL/PIPO 对赛马娘 AI 项目的价值评估
============================================================

赛马娘项目现状（从 uma-train 仓库确认）：
  - 训练框架：MCTS + 神经网络（PyTorch）
  - 训练环境：Colab T4 GPU / Kaggle
  - 数据管道：uma-data 仓库，训练样本格式 (s, π, z) 三元组
  - 模拟器：RamenScenario 拉面杯模拟器
  - 训练方式：自我对弈 → 策略迭代

PIPO 可借鉴点：

  1. 策略更新质量筛选（直接适用）
     当前问题：每轮 MCTS 自对弈产出的数据训练出来的策略更新不一定有效
     PIPO 方案：维护历史策略锚点，新策略对比评估
     适配方式：
       - 维护最近 K=3~5 轮的比赛模拟器评分滑动窗口
       - 每轮训练后自动评估新网络 vs 历史基准
       - 按 rho 反馈标记训练数据质量

  2. 代码实现量评估
     PIPO 核心逻辑约 200-300 行 Python（从 layback_utils.py + core_algos.py 提取）
     不需要引入 verl 框架（太重，针对 LLM）
     需要自行实现回合级（turn-level）的 PIPO 适配

  3. 不适用的部分
     - verl 框架的 LLM 训练管道（完全不同场景）
     - 数学推理/代码 RL/工具使用的 reward 函数
     - PPO 的 token-level 粒度（赛马娘是 turn-level）
