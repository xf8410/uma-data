一、证据等级
================================================================================

CONFIRMED：由结构化 metadata、运行时方法枚举或 MDB 原始数据直接确认。
OBSERVED：由当前插件运行时内存读取观察到，但字段身份或语义尚未完全确认。
INFERRED：由名称、邻域或结构推断，尚缺调用链/字段类型/真实 payload。
UNKNOWN：当前材料无法判断。

二、已确认（CONFIRMED）
================================================================================

1. Gallop.WorkSingleModeData 存在 get_FixedTurnCharaSeed()。
   - 运行时方法转储记录地址: 0x7339dc422c
   - 参数数: 0
   - 转储仅将返回类型粗分为 ptr，不能据此证明它是 [u32;4]。

2. 不同类中存在同名但返回 i4 的 FixedTurnCharaSeed：
   - TrainingBackupDataScenarioOnsenAssistantCommand.get_FixedTurnCharaSeed
   - ITrainingBackupData.get_FixedTurnCharaSeed
   - TrainingBackupDataDefault.get_FixedTurnCharaSeed
   因此同名属性不能跨类混为一种结构。

3. StandaloneSimulator.IRaceRandomGenerator 有四个 GetRandom 重载：
   - 1参数 -> i4
   - 2参数 -> i4
   - 1参数 -> r4
   - 2参数 -> r4

4. 存在具体类 StandaloneSimulator.RaceRandom，并具有对应的四个 GetRandom 重载。
   这证明客户端比赛模拟侧存在具体随机实现候选；“客户端没有任何 RNG/PRNG
   实现”的旧结论不成立。

5. Gallop.ObscuredIdleSingleModeEndInfo 存在 RaceRandomProgramArray getter/setter。
   getter 的粗返回分类为数组类结果，但元素类型仍需运行时字段类型或 formatter
   反序列化顺序确认。

6. metadata 中存在：
   - Gallop.SingleModeRaceRandomProgram
   - Gallop.MsgPack.Formatters.SingleModeRaceRandomProgramFormatter
   - 对应 HTTP Model 与 MsgPack Formatter 源路径字符串
   这支持它是服务器通信模型，但尚未恢复其字段。

7. MDB 原始数据：
   - single_mode_chara_program：225行，角色与育成赛程组配置。
   - single_mode_program：1118行，育成比赛赛程配置。
   - random_group_id 仅12行非零；它是赛程随机组线索，不是训练 PRNG 状态。

三、运行时观测（OBSERVED）
================================================================================

1. 当前插件从 WorkSingleModeData 相关对象的 offset 0x198/408 读取四个 u32，
   并在训练 Hook 前后观察其变化。

2. 在字段类型、getter 返回类型和版本一致性完成验证前，该值应称为：
   “客户端观测到的 RNG 相关四元组状态（observed rng_state）”。

3. 状态字的数值差只是原始特征。特别是：
   s1_after - s1_before 不是已确认的 PRNG 调用次数。

四、合理推断（INFERRED）
================================================================================

1. SingleModeRaceRandomProgram/RaceRandomProgramArray 很可能参与单人模式比赛的
   确定性模拟或重放，但尚不清楚其内容是 seed、随机值数组、程序指令还是其他参数。

2. RaceRandom 可能实现 IRaceRandomGenerator；仍需接口映射、字段、构造器及调用链确认。

3. 服务器是联网育成状态的权威来源，但这不等于客户端完全没有随机计算，也不证明
   服务器在开局时预计算整局所有训练、事件和彩圈结果。

五、当前未知（UNKNOWN）
================================================================================

- WorkSingleModeData.get_FixedTurnCharaSeed 的准确返回类型与对应字段 offset。
- offset 0x198 四元组是否就是该属性、完整 PRNG 状态或某个专用随机流。
- SingleModeRaceRandomProgram 的字段、元素类型和 formatter 顺序。
- RaceRandom 的内部字段、构造输入及算法。
- 训练、事件、比赛是否共用同一随机流。
- 点击训练前客户端是否已持有可直接解析的未来训练结果。

六、明确排除的旧结论
================================================================================

以下结论没有足够证据，不得用于实现或建模：

- “客户端纯展示、零 RNG/PRNG 计算”。
- “服务器开局预计算整局72回合所有随机事件”。
- “训练随机性由 metadata 中的 _seedArray 驱动”。
- “四元组形态可推出 Xorshift128/Xoshiro128”。
- “s1 是随机消费计数器”或“状态字差等于随机步数”。
- “已知 rng_state 即可确定性预测训练结果”。
- “single_mode_program.random_group_id 是训练 RNG 参数”。

其中 _seedArray/_inext/_inextp 位于典型 System.Random 运行库邻域；除非找到训练
业务调用链，否则不能归属于训练 RNG。s_seed 同样必须先确认所属类型。
